# GUI 儀表板排版與展示樣態設計

## 目標

GUI 需讓一般使用者在不接觸 JSON 或 Python code 的情況下完成三件事：

- 選擇參賽團子。
- 完整跑一場小團快跑並觀看畫面。
- 執行多輪模擬並比較勝場、勝率、平均名次與綜合權重排名。

## 主視窗排版

主視窗採儀表板式佈局：

- 視窗預設最大化啟動。
- 外層使用上方 `QTabBar` 加下方 `QStackedWidget` 工作區。
- 上方 tab 固定顯示三個工作區：`單輪模擬`、`多輪模擬`、`設定`。
- `單輪模擬` 工作區包含左側事件紀錄、中央賽道與右側即時狀態表。
- `多輪模擬` 工作區包含場數、CPU worker、進度/ETA 與可點擊 header 排序的結果表。
- `設定` 工作區只顯示目前參賽團子、全域 Seed 設定、作者與版本號，並提供「自訂參賽團子」入口；速度、場數、CPU worker、結果排序等操作性設定留在各自工作區。
- 單輪工作區左側：事件紀錄。
- 單輪工作區中央：標題、抽象橢圓賽道、格子、裝置、團子棋子、堆疊、骰子與播放控制。
- 單輪工作區右側：即時名次表格與本輪行動表格。
- 單輪工作區左右資訊欄固定為相同寬度，中央賽道區使用剩餘寬度，確保最大化與一般視窗模式下賽道都維持在工作區水平正中；左右資訊欄需有足夠寬度，讓事件紀錄、即時名次與本輪行動具備較舒適的閱讀空間。

此設計讓單輪觀看、多輪估算與偏好設定有清楚邊界，避免單一畫面垂直擁擠。
事件紀錄放在單輪工作區左側，團子與 Seed 設定集中在設定工作區，避免執行畫面混入賽前設定。
應用標題不再佔用整個視窗頂部，而是顯示在中央賽道區上方置中；作業系統視窗標題列仍保留完整應用名稱。

## 工作區切換

工作區切換只改變目前顯示頁面，不重建 core 模擬狀態。

- 單輪模擬進行中可以切換到其他頁面查看設定摘要，但參賽團子設定入口維持禁用。
- 多輪模擬進行中可以切換頁面；多輪 worker 繼續執行，回到多輪頁可看到目前進度與 ETA。
- 單輪模擬與多輪模擬彼此不互鎖，可同時執行；切換工作區不會停止任何一個正在執行的流程。
- 設定頁的參賽團子入口使用既有 `ParticipantSetupDialog`。

## 團子選擇

內建資料載入後會轉為 `ParticipantCardState`。
設定工作區顯示參賽摘要；使用者按下「自訂參賽團子」後，在彈出式視窗看到卡片，不需要知道底層 JSON。
完整彈窗規格見 `docs/specs/participant-setup-dialog-design.md`。

一般團子可勾選是否參賽，不限制最多 6 顆，但至少需要 1 顆一般團子。
卡片可顯示 group、初始位置、初始堆疊順序與首回合順序。
布大王固定顯示，並提供兩種模式：

- 干擾者：加入賽道但不列入排名。
- 參賽者：列入排名與勝率統計。

## 單場展示

單場控制包含：

- 開始
- 下一步
- 自動播放 checkbox
- 暫停
- 重置
- 播放速度

每次行動後更新：

- 賽道棋子位置與堆疊。
- 骰子結果。
- 目前第幾輪。
- 即時名次，依核心規則以距離終點與堆疊上下排序。
- 即時名次表格顯示排名、團子棋子、團子名稱、目前格數與賽中/完賽狀態。
- 本輪行動表格顯示本輪行動順序、團子棋子、團子名稱、骰子與狀態。
- 布大王第 1、2 輪不行動時不顯示在本輪行動表格；第 3 輪開始若進入行動順序，顯示布大王與骰子。
- 事件紀錄。

即時名次表格欄位對齊：

- 名次：置中。
- 團子：靠左。
- 格數：置中。
- 狀態：置中。

即時名次與本輪行動表格需關閉文字自動換行。名次、格數、順序、骰子與狀態欄使用較窄固定欄寬；團子名稱欄使用剩餘寬度，至少應能在單行容納約 6 個繁體中文字的團子名稱。
即時名次與本輪行動表格採單格選取，不使用整格填滿選取底色；目前選取格只在該格左側顯示短直線，直線顏色使用 Qt/system palette 的 highlight 色，讓不同作業系統沿用各自的選取色。

本輪行動表格欄位對齊：

- 順序：置中。
- 團子：靠左。
- 骰子：置中。
- 狀態：置中。

事件紀錄顯示規則：

- `第 N 回合行動順序：...` 不縮排。
- `比賽結束，...` 不縮排。
- 其他事件前方加兩個全形空白，方便與回合/結束訊息區分。
- 事件紀錄使用團子與裝置的顯示名稱，不直接顯示內部 id，例如顯示「陸赫斯團子」與「推進裝置」，不顯示 `lu` 或 `advance`。
- 事件紀錄更新前若沒有縱向卷軸，或縱向卷軸已在最底部，更新後自動捲到最底部。
- 事件紀錄更新前若使用者正在往上回看，也就是縱向卷軸不在最底部，更新後保留回看位置，不強制拉到最新事件。
- 地圖格子 tooltip、棋子 tooltip、目前行動者、即時名次等 GUI 使用者可見文字都優先顯示 `name` 或本地化顯示名；除非是必要的除錯、匯出、CLI/API 或內部資料欄位，否則不顯示 id。
- 地圖 tooltip 顯示位置依序嘗試右上、左上、左下、右下；若四個位置都無法完整放入 viewport，最後將 tooltip clamp 到 viewport 內。

自動播放 checkbox 在初始狀態與單場開始後都可操作，用來設定偏好與控制 timer。
開始前勾選後，按下開始會直接進入自動播放。
單場開始後可勾選或取消；勾選時啟動 timer，取消時停止 timer。
按暫停會取消勾選；重置或比賽結束會停止 timer。

第一版先使用抽象橢圓賽道與彩色棋子，不追求官方直播畫面復刻。
棋子內文字使用團子名稱第一個可見字，例如「布大王」顯示「布」。

## 棋盤圖層

中央賽道使用固定圖層順序，避免團子被裝置或下層棋子遮住：

- 賽道底線位於最低層。
- 格子、裝置與終點標記位於賽道上方，但低於所有團子。
- 團子棋子依堆疊順序逐層提高；同格時，上方團子的 `y` 偏移更高，`zValue` 也更高。
- 棋子文字位於棋子本體上方。
- 每顆棋子有淡陰影；目前行動團子有高亮外框，高亮只高於自身棋子，不破壞同格堆疊上下關係。

圖層計算集中在 `dangosim.gui.layers`，讓視覺規則可以用單元測試驗證。

## 多輪模擬

多輪模擬支援 1 到 99999999 場，GUI 場數欄位寬度需可容納 `99,999,999` 等級的輸入。
場數欄位需在每次輸入變更時即時補上千分位逗號，不只在失焦時格式化。
若游標位於逗號旁，Backspace 刪除逗號左側數字，Delete 刪除逗號右側數字，避免使用者只刪到格式化逗號。
GUI 使用背景 worker 執行，避免阻塞主視窗。
使用者可在 GUI 選擇 CPU worker：

- `自動`：依目前 CPU core 數取約 2/3 的 worker；若場數較少，最多不超過場數。
- `全力`：使用目前 CPU core 數；若場數較少，最多不超過場數。
- `1..N`：明確指定 worker 數，`N` 依執行環境可用 CPU core 動態產生。

若使用者設定檔從較多核心的電腦移到較少核心的電腦，且儲存的指定 worker 數超過目前 CPU core 數，啟動時會回退到 `自動`。
正式模擬開始前仍會透過 core 再次限制 worker 數，確保實際 worker 不超過目前 CPU core 數或模擬場數。

執行前會先試跑樣本場數估算總時間，並以 Yes/No message box 告知使用者預估時間。
只有使用者按下 Yes 才正式開始多輪模擬；按下 No 會取消正式模擬並回到原控制狀態。
估算採單 worker 樣本試跑，再依正式 worker 數換算預估時間，避免小樣本被 subprocess 啟動成本放大。
message box 需顯示樣本場數、正式 worker 數、預估時間與是否開始正式模擬的確認文字；其中整數數字需使用每三位一個逗號的千分位格式。
樣本場數規則：

- 總場數小於 10 時，試跑全部場數。
- 一般小批次至少試跑 10 場。
- 大批次依總場數提高樣本量，最多試跑 200 場。

Seed 設定位於 `設定` 工作區，單輪模擬與多輪模擬共用同一組 Seed mode 與固定 Seed 輸入。

Seed 模式：

- 固定 seed：使用者輸入 0 到 2^64-1 的整數 seed，結果可重現。
- 系統隨機 seed：使用 Python `secrets.randbits(64)` 取得作業系統安全隨機來源，並在 GUI 的目前 seed 顯示區顯示實際使用 seed。

Seed 輸入欄位旁需顯示 `固定 Seed：` label。
Seed 輸入欄位只在固定 seed 模式可編輯；選擇系統隨機 seed 時必須禁用，直到切回固定 seed。
系統隨機 seed 模式不得把實際使用 seed 回填到固定 seed 輸入欄位，固定 seed 輸入欄位需保留使用者原本輸入的值。

Python 標準函式庫不保證可指定「CPU 熱噪聲」作為來源；系統隨機 seed 是此專案可攜且務實的隨機來源。

結果表欄位：

- 排名
- 團子
- 勝場
- 勝率
- 平均名次
- 綜合分數

結果表欄位對齊：

- 排名：置中。
- 團子：靠左。
- 勝場、勝率、平均名次、綜合分數：靠右。

結果表高度需至少保留約 7 列可視空間，讓使用者在一般視窗高度下可一次檢視 6 到 7 位參賽者。

結果表排序：

- 預設依綜合分數遞減排序。
- 使用者可直接點擊結果表 header 排序。
- 排名欄不可排序，只顯示目前表格排序下的視覺排名。
- 可排序欄位點擊同一 header 時依序循環：遞減、遞增、不使用此欄排序。
- 若某欄進入「不使用此欄排序」，結果表回到預設綜合分數遞減。
- 遞減排序時排名欄顯示 `1..N`；遞增排序時排名欄顯示 `N..1`。
- Header 需顯示目前排序方向，例如 `綜合分數 ▼` 或 `勝率 ▲`。

多輪模擬執行中：

- 顯示進度條，格式為 `已完成 / 總場數`。
- 顯示 ETA。
- 關閉場數、Seed 模式、Seed 輸入與執行按鈕。
- 啟用停止模擬按鈕。
- 結果表 header 排序保持可操作。

停止模擬時，worker 會收到取消請求，停止後恢復初始多輪模擬控制狀態。
多核心模式以 chunk 為取消邊界；停止後不再排入新 chunk，已在執行中的 chunk 完成後回報目前累積結果。

## 使用者設定

GUI 會自動儲存一般使用者偏好，不要求使用者編輯 JSON 或 Python code。
設定檔位置為 `%APPDATA%\DangoSimulator\settings.json`；測試或特殊環境可用 `DANGOSIM_SETTINGS_PATH` 指定替代路徑。

目前儲存欄位：

- 參賽一般團子 id 清單。
- 布大王模式：干擾者或參賽者。
- 每顆團子的參賽狀態、初始位置、初始堆疊順序與首回合順序 override。
- 單場播放速度。
- 單場自動播放 checkbox 狀態。
- 多輪模擬場數。
- Seed 模式：固定 seed 或系統隨機 seed。
- Seed 輸入欄位內容。
- CPU worker 選擇：自動、全力或指定數量。
- 多輪結果 header 排序欄位相容欄位。

啟動 GUI 時會讀取並套用設定；若設定檔不存在、格式錯誤、數值超出範圍或包含未知團子，會回退到安全預設值。
使用者變更上述控制項時會自動儲存。

## 控制狀態

初始狀態：

- 啟用：開始、參賽團子設定、速度、自動播放 checkbox、多輪模擬執行按鈕、場數、Seed 模式、CPU worker、結果表 header 排序。Seed 輸入只在固定 seed 模式啟用。
- 關閉：下一步、暫停、重置、停止模擬。

單輪模擬開始後：

- 啟用：下一步、自動播放、暫停、重置、速度；若多輪模擬尚未執行，多輪模擬執行按鈕、場數與 CPU worker 仍可操作。
- 關閉：開始、參賽團子設定、Seed 模式、Seed 輸入。

多輪模擬開始後：

- 啟用：停止模擬；若單輪模擬尚未執行，開始與自動播放 checkbox 仍可操作。
- 關閉：多輪模擬執行按鈕、場數、CPU worker、參賽團子設定、Seed 模式、Seed 輸入。

重置後恢復初始狀態。
任一一般團子抵達終點造成單輪比賽結束時，也恢復到可直接按「開始」開啟下一場的狀態，不需要先按重置。

只要單輪模擬或多輪模擬任一流程正在執行，參賽團子設定與 Seed 設定都不可編輯。若兩者同時執行，多輪結果完成時不可覆蓋正在進行的單輪模擬 seed 顯示。

## 綜合分數

預設公式：

```text
綜合分數 = 勝率 * 0.70 + 平均名次反向分數 * 0.30
```

平均名次反向分數：

```text
(參賽者數量 - 平均名次) / (參賽者數量 - 1)
```

此公式讓高勝率優先，同時保留穩定前段名次的價值。

## 邊界

GUI 不直接修改 `RaceSimulator` private state。
GUI 透過 `GuiRaceController` 與 `run_batch_simulation` 存取 core。
未來若要做拖曳式賽道/裝置編輯，應另開規格，不混入本設計。
