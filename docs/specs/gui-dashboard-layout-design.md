# GUI 儀表板排版與展示樣態設計

## 目標

GUI 需讓一般使用者在不接觸 JSON 或 Python code 的情況下完成三件事：

- 選擇參賽團子。
- 完整跑一場小團快跑並觀看畫面。
- 執行多輪模擬並比較勝場、勝率、平均名次與綜合權重排名。

## 主視窗排版

主視窗採儀表板式佈局：

- 左側：團子卡片多選、技能摘要、布大王模式。
- 中央：抽象橢圓賽道、格子、裝置、團子棋子、堆疊、骰子與播放控制。
- 右側：即時名次與事件紀錄。
- 下方：多輪模擬設定與結果表。

此設計讓主要流程都留在同一個視窗，適合反覆調整參賽者並快速重跑。

## 團子選擇

內建資料載入後會轉為 `ParticipantCardState`。
使用者只看到卡片，不需要知道底層 JSON。

一般團子可勾選是否參賽。
布大王固定顯示，並提供兩種模式：

- 干擾者：加入賽道但不列入排名。
- 參賽者：列入排名與勝率統計。

第一版允許 1 到 6 顆一般團子參賽，布大王可額外加入。

## 單場展示

單場控制包含：

- 開始
- 下一步
- 自動播放
- 暫停
- 重置
- 播放速度

每次行動後更新：

- 賽道棋子位置與堆疊。
- 骰子結果。
- 即時名次。
- 事件紀錄。

第一版先使用抽象橢圓賽道與彩色棋子，不追求官方直播畫面復刻。

## 多輪模擬

多輪模擬支援 1 到 100000 場。
GUI 使用背景 worker 執行，避免阻塞主視窗。

Seed 模式：

- 固定 seed：使用者輸入 0 到 2^64-1 的整數 seed，結果可重現。
- 系統隨機 seed：使用 Python `secrets.randbits(64)` 取得作業系統安全隨機來源，並在 GUI 顯示與回填實際使用 seed，方便切回固定 seed 重跑。

Python 標準函式庫不保證可指定「CPU 熱噪聲」作為來源；系統隨機 seed 是此專案可攜且務實的隨機來源。

結果表欄位：

- 排名
- 團子
- 勝場
- 勝率
- 平均名次
- 綜合分數

排序模式：

- 綜合分數
- 勝率
- 平均名次

## 綜合分數

預設公式：

```text
綜合分數 = 勝率 * 0.70 + 平均名次反向分數 * 0.30
```

平均名次反向分數：

```text
(參賽者數量 - 平均名次) / (參賽者數量 - 1)
```

此公式讓高勝率優先，同時保留穩定前段名次的價值。

## 邊界

GUI 不直接修改 `RaceSimulator` private state。
GUI 透過 `GuiRaceController` 與 `run_batch_simulation` 存取 core。
未來若要做拖曳式賽道/裝置編輯，應另開規格，不混入本設計。
